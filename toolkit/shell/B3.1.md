# Rust notification banners, B3.1 (#1050)

This step implements notification banners for #1050; Notification Center/calendar/clock routing is B3.2
and does not ship here. Reuse Notifications1, existing settings and icon_memory.
No TS shell, new notification server, CI workflow configuration or live-session change.
The existing sessiond integration now asserts history retention on sender expiry.

Banners occupy the bar's own layer surface, below its right group, at the CC's
grid width. The bar expands while banners need space; input is the union of its glass
and card glass, not the empty gaps. A fullscreen output can show banners above
its window without exposing the hidden bar. Lock always hides notification data.
Right-dock avoidance and panel geometry are shared with the CC; no dock behavior
is changed. Cards declare their material to Hyalo and paint dark-skin content.

One canonical stack holds at most four visible entries. A fifth retires the
oldest non-critical entry without Dismiss. If all four are critical, it retires
the oldest critical; ordinary daemon history remains intact. Replacements keep the slot and reader identity, replace
content and restart the timer; stale content actions are retired. Sender positive
timeout overrides the configured popup timeout; zero and critical never expire.
Hover pauses and leaving restarts the full countdown. Local timeout/cap/panel
suppression preserves ordinary history. Transient records expire (reason 1) when
their banner times out, is evicted, or is suppressed, including on arrival. Only close/swipe/body-without-default dismiss;
explicit/default actions invoke the daemon, respecting resident notifications.

DND, detected gamespace game silencing and an open CC suppress ordinary banners;
critical cuts through those gates. Source-owner loss retires the stack and old
actions; subscribing precedes owner hydration. Initial history
is not replayed as fresh banners. A banner chooses one output, not every monitor.

App artwork uses the one icon memory: desktop-entry, unambiguous registry match,
non-generic app_icon, existing neutral asset. Thumbnail work is bounded and off
input/render callbacks. The notification card is reusable for B3.2, with one-line
summary, two-line body and action buttons; long action lists remain operable.

Each visible card has NOTIFICATION/critical ALERT semantics, app+summary name,
body and buttons. Appearance announces once; replacement does not flood live
announcements. dumpState reports the native stack. Keyboard/AT-SPI actions never
retarget a retired owner or content identity. User actions carry activation tokens.

The daemon no longer expires records on a sender timer. Native actions deliver
the token to the sender; the lifecycle and additions are documented below.

Verification uses a private bus, settings, daemon, software Hyalo and notify-send:
normal/critical/image/actions/replacement, four-card cap, timeout/hover, suppression
and critical exceptions, input gaps, close/swipe/action round trips, token and
AT-SPI announcement/state. Each assertion has a deliberate failure control.
Keep actual physical-session/Orca/multi-monitor acceptance separate. Do not build
while headless tests run; check disk before builds and stop below 10 GiB free.

## Native wire additions

`expire_timeout` is now presentation metadata in the daemon for every renderer.
There is no host registration or daemon expiry timer. The existing List/Dismiss/
InvokeAction and public notification interface retain their signatures and store
shape. `Notified` JSON adds a runtime `revision` counter (not persisted):

- `ExpireTransient(u id, t revision)` removes only a current transient record,
  with NotificationClosed reason 1. A stale revision or ordinary record is rejected.
- `DismissBanner(u id, t revision)` is the revision-checked equivalent of Dismiss.
- `InvokeActionWithToken(u id, s key, s token, t revision)` validates both the
  record revision and declared key, emits ActivationToken before ActionInvoked,
  both directed to the Notify sender's unique name, then resolves non-resident
  records with reason 3. A gone sender is logged once per record; resolution still
  happens. Legacy InvokeAction is unchanged.

The renderer pins the unique daemon owner and requires the additive methods;
old daemon binaries report banners unavailable. It subscribes before owner
hydration and never calls List to replay historical records as fresh popups.
A revision checked in the daemon also closes the replacement race after a worker
has left the hub. Shell instance/content identities additionally retire pending
activation requests and stale reader callbacks.

Pointer/keyboard actions use their delivered input serial. An assistive DoAction
without a serial requests root keyboard focus explicitly, waits for its actual
wl_keyboard.enter, and uses only that root's enter serial to request a token.
The toolkit clears this proof on leave or keyboard capability loss. No serial is
invented and no virtual input is injected. Focus requests support Tab/Shift+Tab,
Space/Enter and Escape; banner arrival never takes keyboard focus.

Cards use the CC grid width (364), hang (8) and square corner (38). Their glass
uses controlCenter tokens, with white ink. Right-dock envelope avoidance is one
helper shared by the CC and banners. Actions beyond three use bounded two-action
pages plus More actions; every key in the bounded model (32 actions maximum) remains accessible. Body/summary strip
markup and decode entities once, matching TS plain-label behavior. Text uses the
CC's real-face-or-regular fallback; a missing bold face must never hide a summary.
Versioned Image keys in the process-wide icon memory prevent overwritten image
paths from reusing old pixels. There is no per-card decoded cache or worker pool.

`GetNotificationState()` is additive to Shell1, behind `notifications:banners`.
Native dumpState includes that JSON; GetState's existing typed tuple is unchanged.
B3.2's nc/clock routing remains unavailable.

## Local verification

With matching, already built binaries and exported settings data:

```sh
HYALO_BIN=/path/to/nidara-hyalo \
NK_DOCK_BIN=/path/to/nidara-shell \
NK_SESSIOND_BIN=/path/to/nidara-sessiond \
NIDARA_IPC_BIN=/path/to/nidara-ipc \
NK_SETTINGS_DATA=/path/to/settings-data \
NK_WIDGETS_LOG=/path/to/evidence \
toolkit/shell/check-notifications-headless.sh
OUT=/path/to/model-controls toolkit/shell/check-notification-model-controls.py
```

The real-wire checker uses notify-send (including selected-action/token file
descriptors), the daemon, AT-SPI events/DoAction, actual pointer/keyboard input,
and a private GTK client behind the cards. It checks text/image pixels, replacing
an image in place, retired revision rejection, card gaps, right-dock/CC alignment,
critical over CC/fullscreen and native dumpState. The report records each oracle
and its contradictory-observation control. The separate pure-model runner makes
eleven actual source mutations in copies, requires the named test to fail (not a
compiler/startup error), then restores/passes the original. The existing sessiond
integration also rejects the previous daemon at the history-retention assertion.
The new graphical checker is local/nightly-sized; no CI workflow is wired here.

Private validation does not establish installed physical-session behavior,
multiple-monitor hotplug/scaling, real-game transitions, lock-screen presentation,
Orca speech or a real application's handling of default-action activation tokens.
Those remain in the PR's "not seen live" list. The full session suite also has a
pre-existing long-worktree limitation: config::followers' cursor test binds a path
built from CARGO_MANIFEST_DIR that exceeds SUN_LEN here. Its source is unchanged;
the failure is retained and the rest of the suite is run with only that test
excluded. B3.2's journal/retention/bulk dismissal work remains separate.

HiDPI artwork is checked separately with `NK_NOTIFICATION_HIDPI_CHECK=1` on the
same wrapper: it sets scale in the disposable compositor's initial configuration
and verifies registry and image requests against the renderer's physical pixel
scale. This avoids resizing the nested EGL window during the assertion. A separate
mid-session scale probe hit EGLCreateSurface(BadAlloc)/ContextLost in winit/Mesa;
its failed run is retained. It is not evidence of installed dynamic-scale support.
The normal checker also proves that a shell restart does not replay stored history
as fresh banners, and that unknown senders decode the reference neutral glyph.


## Review notes and proposed nightly coverage

Lock currently retires every banner, including critical ones, and notices received
while locked do not become popups at unlock. Their ordinary daemon records remain; transient records expire. Critical
reappearance after unlock is a behavior gap; this step does not claim that it is
implemented. Notification Center access to those records belongs to B3.2.

Proposal for owner approval: run the normal headless checker and its HiDPI-startup
mode in the nightly using matching already-built binaries. The recorded local runs
took about 32 s and 4 s respectively, excluding compilation; allow roughly 1–2 min
and a 5 min job timeout for software-renderer variability. The model mutation runner
can accompany the ordinary model tests. Reuse build artifacts so this adds no second
full Rust build. No workflow configuration is changed by this proposal.


Restored-record revisions, revisions in List and resolving actions with no known
sender are explicitly reserved for B3.2 by the owner. B3.1 consumes only fresh
Notified events; it neither replays List into banners nor extends those history
APIs in this step.


The notification watcher subscribes before reading its initial owner, then blocks
on notification/NameOwnerChanged messages. It does not poll GetNameOwner in idle.
On bus loss the subscription workers release their senders and the disconnected
inbox retires visible banners. The private checker observes actual GetNameOwner
traffic during a quiet window; the previous binary fails that oracle. It also
restarts the private daemon to prove owner-loss retirement and fresh-event recovery.

Entity decoding reads the original input once for both named and numeric forms.
For example `&#38;lt;` becomes the literal `&lt;`, not `<`; emitted characters are
never rescanned. A dedicated mutation restores the second decode and must fail.


Activation-token failures remain token guarded: the card displays an accessible
error and allows retry; it never invokes a tokenless action. Errors have a reserved
row and belong to the exact instance/content pair, so a late failure cannot label
a replacement. The private checker withholds replies from its own compositor to
exercise the real timeout, resumes it in finally, and checks a successful retry.
Transient expiry is renderer-driven and pinned to the unique daemon owner and
record revision. It does not add a daemon countdown that would break hover pause.
