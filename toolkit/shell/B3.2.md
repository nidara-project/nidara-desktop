# Notification Center and durable history, B3.2 (#1050)

Contract from #1050, owner-authorized in the Codex chat on 2026-11-08.
B3.1 is main 59a1b964. This step adds the whole B3.2 slice in its own PR.

- Clock and Shell1 `nc` toggle the panel on the bar surface. Escape/outside close;
  NC and CC exclude one another. Lock closes and redacts both. Calendar shows the
  local month/today and supports previous/next month and Today. Weekday labels
  use the clock's GLib locale formatting; the first weekday follows glibc's locale
  reference date and first_weekday, read once through `locale`. Shell startup
  initializes LC_TIME from the environment before spawning any threads; without
  GTK initialization, otherwise GLib's clock/calendar date words stay in C locale.
- Newest-first application groups, count when collapsed, relative age refreshed
  once per minute; no transient records. One Card renderer with banners. Rows are
  indexed on data/expansion changes, then binary searched by viewport; only visible
  cards request icons, lay out, paint and enter the accessible tree. Scroll and
  keyboard/AT-SPI actions remain operable without building hidden cards.
- Dismiss one/group/all is guarded by current daemon owner. Group/all use one bus
  request and a single removal journal entry; only visible rows animate for a
  fixed interval. Errors belong to the issuing view/content. Actions keep tokens.
- Snapshot and an ordered change sequence close hydration races. Runtime revisions
  are assigned to restored records and included in List. A missing/dead sender
  logs once and resolves an action rather than rejecting restored history.
- Ordinary noncritical records age out after 7 days. Critical records only leave
  by explicit dismissal/action. The 2000 safety ceiling removes oldest eligible
  noncritical records before today. It is deliberately soft when protected records
  alone exceed it: never discard today's records, a critical, or a new arrival.
- Append one JSON Lines operation per change; group/all removal uses one operation.
  Compact atomically through a same-directory temporary file and rename, at startup
  and around twice the live set. Import legacy state.json once and remove it only
  after successful journal publication. No new dependencies. Trailing partial
  journal writes are recoverable; invalid interior input is preserved byte for
  byte as `.broken-<timestamp>`, while services start with empty history. Image
  files belong to live references, with no independent 150-file cap.
- A shell restart hydrates history without replaying banners. Transient leftovers
  from a retired renderer expire during hydration, with revision guards.

## Wire and storage details

`List()` keeps its string result, adding runtime `revision` to each record.
`Snapshot()` returns `(t sequence, s records_json)` under the same state lock.
`Changed(t sequence, s operation_json)` carries either `{ "put": record }` or
`{ "removed": [ids], "reason": reason }`. The watcher subscribes first, applies
Snapshot as history, then ignores queued changes at/before its sequence. A fresh
put after that barrier can show a banner; historical records never do. An invalid
or over-limit individual record is logged and skipped, without disconnecting the
rest of the stream. Owner changes retire all old content/view identities.

`DismissGroup(s key)` uses desktop-entry, or the bounded app name when absent.
`DismissAll()` clears non-transient history. Each adds one removal operation and
emits one private `ResolvedBatch(au ids, u reason)` plus the ordered Changed event;
NotificationClosed goes to each original sender. Ordinary single-record methods
retain their old Resolved signal. There is no per-row UI call cascade.

The journal is `nidara/notifd/history.jsonl` in the private cache directory:
`{"op":"put","notification":{...}}` and `{"op":"remove","ids":[...]}`.
A single writer under the daemon state mutex attempts append and sync before replying.
This is O(record size), or O(ids) for a bulk removal, rather than O(history size).
Compaction is amortized, through a synced temporary file/rename and directory sync.
A final incomplete line is unacknowledged work and is discarded on recovery.
Invalid complete/interior data is quarantined without changing its bytes; if it
cannot be preserved, writes stay disabled until preservation succeeds. Storage
errors never prevent the daemon's other services from starting, nor live
notifications from arriving, being dismissed or cleared. One warning marks each
write outage. A gap marks history non-durable: the next successful write compacts
the current live model first, so missed removals are not resurrected. A failed
optional startup compaction still allows appends to an otherwise valid journal.
Changes made during an outage can be lost if the daemon exits before recovery.
Only generated hash images inside the owned cache are collected; external image
paths and unrecognized files are never deleted. Both image-path spellings count.
Retention sleeps until the next expiry/local midnight and wakes on model changes;
an empty or critical-only history has no periodic maintenance wakeup.

## Renderer identities and cost

The history/group row index is rebuilt on data or disclosure changes. Scrolling
binary-searches it, then builds only intersecting rows. Full hydration/indexing is
O(history); steady layout, painting, artwork requests and reader projection are
bounded by the viewport. A collapsed app shows its newest card and count. Card
identity/content guards are unchanged; relative time is presentation-only.

NC controls retain their id across unrelated arrivals. Every panel view or daemon
change retires those ids, so a valid Clear all press is not discarded because a
new card arrived, and an old view cannot clear a reopened one. Historical cards
use Panel semantics, avoiding a flood of old NOTIFICATION announcements. Tab,
Shift+Tab, Enter/Space, PageUp/PageDown and the reader scroll/disclosure controls
operate the visible list. NC keeps exclusive keyboard focus while open for Escape.

Hyalo renders the one continuous CC-sized outer pane. Cards share content and
input code with banners. Critical banners sit immediately to the NC's left while
it is open, avoiding overlap. Clear animates only departing visible cards with a
150 ms compositor opacity transition on an input-empty child layer; the remainder
is removed as one model change. There is no row-count-based delay. The eight-wash
compositor budget is reserved for navigation, today, hover and keyboard focus;
row headers do not each consume a resting wash.

## Verification and limits

`check-nc-headless.sh` uses a private daemon/bus/settings/software compositor and
2000 imported records. It exercises calendar pixels and selected-date semantics,
clock and real CLI, grouping/viewport/disclosure/scroll, CC exclusion, suppression
and critical exception, shell reload (including transient cleanup), daemon reload
and restored token actions, one group/all clearing and journal append observations.
`check-notifications-headless.sh` remains the B3.1 regression check. Both share one
fixture. `check-history-controls.py` mutates source copies and requires failures
at named retention/journal/calendar/viewport tests, then restores/passes them.
No new CI workflow is wired; these graphical checks are a nightly proposal with
matching prebuilt binaries, not a second full build. Do not compile during them.
`session/daemon/check-store-failures.py` separately exercises real private-daemon
startup with a corrupt interior line and Config1 availability, simulated ENOSPC
via a private `/dev/full` symlink, denied writes, live clearing, recovery/restart
and a 100-notification burst. It never fills the filesystem or changes the session.

Not established here: installed physical-session behavior, real multi-monitor
hotplug, tiny/rotated outputs, real application focus after consuming a token, or
Orca speech. An unknown restored sender resolves/logs; it cannot receive an action
or launch an application which no longer has a sender. Initial lock still clears
critical popups without replay at unlock, as documented in B3.1; the NC preserves
ordinary history for access after unlocking. A pre-existing follower unit test
uses a manifest-relative socket path exceeding SUN_LEN in this long worktree;
its source is unchanged and its exclusion must be reported with local evidence.

Native bulk Changed/ResolvedBatch are published immediately after the journal and
model commit, before per-sender NotificationClosed delivery and image collection.
The renderer therefore starts its fixed animation without waiting for 2000 signal
roundtrips. The checker times the accessible empty-state event, not a List call
which waits on the daemon mutex. Earlier runs with the retained pre-fix renderer
showed its one-second idle interval delaying layer cleanup. The final checker
also measures the armed-to-finished interval separately from daemon delivery.
The bar shortens its wait only while the clear layer is active, then returns to
its ordinary idle interval. Signal failures still complete record metadata/image
retirement before being reported; the durable change is never silently rolled back.
