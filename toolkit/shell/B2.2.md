# B2.2 implementation contract (#1015)

Base: main 2903b277. Owner directly authorized #1015 in the Codex chat.
No dock*.rs/geometry.rs edits, CI/config changes, installation or owner-session writes.

Details replace the CC grid inside the same bar surface. Back/Escape restores the grid;
outside click closes the CC and cancels outstanding secret entry. Normal right-click
opens only the tile's own detail, never editing. Keyboard and AT-SPI must reach every
real control; changing service state is authoritative, pending/failure stays visible.
Lists are bounded/scrollable; semantic identities must survive reorder/removal.

Read Network1/Bluetooth1 snapshots and Audio1/Media1 objects through the existing
status watchers. Discard unavailable state rather than showing stale choices. Writes
run off the UI thread; no nmcli, TS bridge or optimistic success. Network credentials
use the Network1 registered secrets renderer, current owner/request ID and its timeout;
never process arguments, accessibility text, Debug or logs. Connect cannot block replies
to a secret question. Enterprise/hidden profile editing is not invented by the CC.

Wi-Fi: radio, scan, named networks, saved/current state, join/disconnect and password
questions. Bluetooth: power and actual devices, connect/disconnect. Audio: output
selection, output/application volume and mute. Media: Auto/player selection and existing
transport controls, capability-gated seek. Night Light: enabled, temperature and schedule.
Brightness at 1x1 gets its actual slider. Focus and dark mode have no TS detail.
Screenshot: area/screen/window, Save/Copy. Recording: screen/region, audio choice,
Start/Stop, observable running/failure state. Close the CC before capture; own the child
recorder and signal only that process. Reuse stored recording preferences and XDG dirs.
No shell command interpolation, global pkill or claims of recording before spawn.
Glass/veil/washes are Material groups/states, fallback paint only without the protocol.

Product comparison (2026-11-06):
- GNOME's Wi-Fi quick settings joins a network and prompts for a password:
  https://help.gnome.org/gnome-help/net-wireless-connect.html
- GNOME's capture UI chooses screen/area/window and has visible recording Stop:
  https://help.gnome.org/gnome-help/screen-shot-record.html
- KDE exposes per-device and per-application audio controls:
  https://docs.kde.org/trunk_kf6/en/plasma-pa/kcontrol/plasma-pa/index.html
Keep useful TS behavior, but report missing enterprise/hidden profile editor, Bluetooth
pairing flow and unified visual capture chooser as product gaps rather than silently
imitating a more complete settings application or starting TS as a fallback.

Verification: meaningful before/after unit controls; private bar harness with Network1
stand-in covers list and action, accessibility Activate/SetValue and close paths. Native
capture geometry/codec/deadline unit tests and a real PNG/video run with an explicitly
modified test client (stock wf-recorder 0.6 cannot bind software winit DMA-BUF v3;
see CC.md); real-session/hardware acceptance
remains distinct. Unit tests, selected Clippy/rustfmt, skill and diff checks. Check disk
before builds (stop below 10 GiB); no builds while headless checks run.
