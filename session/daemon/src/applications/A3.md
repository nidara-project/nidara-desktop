# Applications1 A3: observation, foreground usage and Unity

A3 is implemented inside the opt-in Applications1 service. It consumes H1 from main,
with no compositor, dock, preferences-registry or live-session changes. The
consumer contract below is fixed before implementation and agreed with D2; UI paint belongs to D2.

## Consumer wire

Existing method signatures remain unchanged. Apps add `Launcher:a{sv}` with
Count:x (nonnegative), CountVisible:b, Progress:d (finite 0..1),
ProgressVisible:b and Urgent:b, always present with zero/false defaults.
ForegroundScore:d is normalized committed foreground seconds, never launch
count. NewlyObservedAt:d is wall-clock observation time; IsNew:b has no expiry.

UsageRevision/LauncherRevision are independent counters. Changed domains are
usage (scores/new markers), launcher (Unity), matching (window links), and the
existing launches. These cannot change LayoutRevision or app Generation.
Search returns the actual UsageRevision. App records in immutable pages retain
the state captured by GetSnapshot.

Root availability is explicit: UsageAvailable, NewAppsAvailable,
MatchingAvailable, HyaloEpoch:s, LauncherAvailable and
LauncherHydrationIncomplete. The last flag describes unknown initial Unity
state when the compatibility name is occupied or signal continuity was lost;
it does not invalidate fresh post-subscription updates. LauncherAvailable=false
clears display. Missing/unknown entries use the false visibility defaults.

WindowMatches and WindowMatchesNext use the existing bounded pages and
ResolveWindow(epoch,hyaloEpoch,windowId). HyaloEpoch combines the compositor run
epoch with a fresh local connection identity. Matching tiers are exact app ID,
exact StartupWMClass, exact Flatpak metadata, then exact initial app ID.
Ambiguity is explicit; titles/executable substrings never resolve identities.

GetLaunch adds HyaloEpoch, WindowId, Correlation (activation-token,
app-match-after-launch or none), CausalConfirmed and an explicit observation
reason. States can become window-observed/existing-window-activated, failed or
timed-out-unknown. Dispatch never implies window/focus. Completion flags describe a past observation,
not the window's current presence/focus. Weak fallback needs a
baseline and one unambiguous outstanding request, and never confirms causality.
An observation terminal does not cancel later argv invocations in a multi-file
dispatch. Original-peer/generation/deadline checks still govern effects.

AcknowledgeNew retains its signature. Its explicit AppAcknowledge operation
permits Shell/Launcher/Settings; other callers require control plus config-write.
It grants no generic configuration, launch, focus or window operation.

## Accounting and persistence

Only a matched focused unminimized/visible app in a coherent, active, unlocked,
awake, non-idle session starts a watch. Split at each focus_transition (never the
coalesced focus_changed), mapping/identity, lock, idle, seat and sleep boundary.
Serial gaps, epoch changes, invalid payloads or disconnect discard the tentative
watch and require a new snapshot; no interval is inferred across loss/restart.
Monotonic microseconds account time. Duplicate events cannot add usage twice.

The pending uninterrupted watch stays separate from committed seconds, including
at disk checkpoints. Idle commits at most min(boundary, watch start + 30 s).
This cap is not last-input + 30 s or idle-event - 30 s. Active resumption starts
a fresh watch. A crash can lose tentative usage; it cannot credit that usage by
wall-clock time after restart. Public ranking uses committed seconds only.

Baseline changes and first-foreground marker acknowledgement commit before
publication. Ordinary committed-time writes coalesce at up to 1 Hz; nonzero
scores decay/checkpoint every 30 s. Explicit acknowledgement is synchronous.

State version 1 lives in $XDG_STATE_HOME/nidara/applications-v1.json, bounded,
0600 and atomically replaced after fsync. Existing TS app-frequency.json is
untouched. Committed seconds decay with a 14-day half-life; wall time only
advances decay checkpoints and clamps backward clocks at zero. Scores normalize
as seconds/(seconds+3600). Search keeps lexical tiers, with at most 0.45 usage
bonus and usage tie-breaking; IsNew never affects ranking.

The first complete healthy catalogue establishes the durable baseline without
marking existing apps new. Later IDs absent from that baseline become newly
observed at observation time, including additions while stopped. Healthy
removal/re-addition is new; degraded scans never replace the baseline. Metadata
updates do not reset markers. Confirmed foreground use or explicit durable
acknowledgement clears the marker. No expiry/timed tombstone is introduced.
Corrupt/unreadable/future state fails closed with a reason rather than treating
all apps as new. Writes are bounded/coalesced; pending time is never serialized.

## Transport and Unity

Subscribe with H1's event_stream snapshot barrier. Validate run epoch, contiguous
serial and nondecreasing monotonic timestamps. A launch token is observed before
dispatch. Since H1's request reply has no epoch, observe_launch and a snapshot
are read on the same request connection, then matched to the live observation
connection. Buffer a bounded number of early outcomes; never persist/broadcast
activation tokens. An unavailable observer does not invent correlation or retry
an application launch. Lock/loss/removal terminates visual observation.

Unity ingests the Update(s,a{sv}) signal on com.canonical.Unity.LauncherEntry,
from any object path, before DoNotQueue claim of com.canonical.Unity. It never
implements an Update method or steals the name. The key is unique sender +
object path + exact application://DesktopId. Count must be signed int64 >=0;
progress is finite and clamped. Unknown keys are ignored within the payload
budget; invalid recognized fields reject the update atomically.

Cap 256 senders, 1024 entries and 64 KiB per message. Latest updated whole
sender entry wins, retaining its own absent fields; never sum senders. Publish
at most 10 Hz per app. Sender loss immediately removes its state and recomputes
from survivors. Unknown app IDs never create apps. Unity is a cooperative
presentation claim; it confers no permission and executes no quicklist/action.

Primary comparisons: [GNOME's usage accounting](https://gitlab.gnome.org/GNOME/gnome-shell/-/blob/main/src/shell-app-usage.c)
provides the pending-watch idle cap; its seven-second quantization, normalization
and timed cleanup are not adopted. [KDE's launcher model](https://invent.kde.org/plasma/plasma-workspace/-/blob/master/libtaskmanager/launchertasksmodel.cpp)
keeps launcher identity separate from presentation. The Unity signal contract
is retained as a compatibility boundary, not an arbitrary action API.

`applications3-check.py` creates a real private bus, independent real Unity
signal senders, a fake coherent H1 server, fake systemd and disposable Python
applications. It covers idle's pending-watch cap, metadata/new-marker behavior,
restart, explicit acknowledgement consent/read-only state, root outage recovery,
window matching/gap/resync, typed signed counts, malformed/oversized/NaN updates,
latest whole sender with partial updates and sender-loss fallback, passive
compatibility-name contention/recovery, an early token result before its reply,
and shared immutable app/matching page-session closure. Future/corrupt durable
state remains unavailable and unchanged. Unit tests use a fake monotonic clock
for cap/decay/loss/boundaries, ambiguity, budgets and multi-file dispatch safety.

H1 input is bounded to 8 MiB per line and 4096 windows. Candidate diagnostics
are capped at 16 IDs/8 KiB, with CandidateCount and CandidatesComplete so a
bounded diagnostic never becomes a false exact match. Root snapshots are
bounded to 2 MiB, pages to 256 records/512 KiB, and retained snapshot domains
share the same caller-bound session/32 MiB budget. Closing any token closes all
its continuation domains; read both domains before closing. If only matching
needs pages, AppsNext supplies one empty terminal app page, allowing older
app-only clients to close the same session without understanding the added
matching collection.

The fixture's epochs/serials/times are synthetic. This does not establish a
combined real H1/sessiond run, real cgroups/portal attribution, installed usage
or login startup, painted counters/progress, physical activation serials,
VT/logind hardware boundaries, accessibility or voiced Orca. A3 installs nothing,
changes no workflow/configuration registry and does not modify the daily TS UI.
